# Инструкция по созданию тестовой карты

## Способ 1: Использовать готовый GLB файл

1. **Скачайте готовый тестовый куб:**
   - Перейдите на https://threejs.org/
   - Найдите примеры GLB файлов
   - Или используйте любой готовый GLB файл

2. **Поместите в правильную папку:**
   ```bash
   client/public/models/map_test1.glb
   ```

## Способ 2: Создать карту в Blender

1. **Установите Blender** (если не установлен)
   - https://www.blender.org/download/

2. **Создайте простую сцену:**
   - Откройте Blender
   - Delete стандартный куб
   - Add → Mesh → Cube (для тестирования)
   - Add → Mesh → Plane (для пола) и масштабируйте (S + Z = 100)

3. **Добавьте материалы (опционально):**
   - Выберите объект
   - Перейдите в Shading
   - Добавьте простой материал

4. **Экспортируйте в GLB:**
   - File → Export → glTF Binary (.glb)
   - Выберите папку: `client/public/models/maps/<id>/` (например `client/public/models/maps/my_map/`)
   - Назовите файл: `map_<id>.glb` (например `map_my_map.glb`)
   - Нажмите "Export glTF Binary"

5. **Добавьте карту в манифест** — файл `shared/maps/maps.json`:
   - укажите уникальный `id`, отображаемое `name` и `spawnCount` (лимит игроков на карте);
   - в поле **`path`** — URL-путь к GLB от корня сайта (файл лежит в `client/public/`, поэтому путь начинается с `/models/...`);
   - опционально **`hdrPath`** — путь к HDR для освещения окружения, если экспортировали его рядом с GLB.

   Пример записи для `client/public/models/maps/my_map/map_my_map.glb`:

   ```json
   {
     "id": "my_map",
     "name": "My Map",
     "spawnCount": 4,
     "path": "/models/maps/my_map/map_my_map.glb",
     "hdrPath": "/models/maps/my_map/map_my_map.hdr"
   }
   ```

   Без записи в `maps.json` карта не появится в выборе и не загрузится в игре.

## Коллизии (чтобы игрок не проваливался сквозь пол)

Визуальная геометрия уровня **сама по себе не участвует в физике**. При загрузке GLB `MapBuilder` создаёт статические тела Ammo только для мешей, помеченных как коллайдеры.

### Как пометить объект коллайдером

Подойдёт **любой** из вариантов:

| Способ | Условие |
|--------|---------|
| Имя меша | начинается с `collision` (например `collision_floor`, `collision_wall`) |
| Custom Property в Blender | boolean `collider` = `true` (попадает в `userData.collider` в GLB) |

Меши с именем `collision…` после загрузки **скрываются** (`visible = false`) — их не видно в игре, они служат только для физики. Визуальный пол/стены делайте отдельными объектами с материалами.

### Типы коллайдеров (по имени меша)

`MapBuilder` выбирает форму тела по имени:

| Имя | Физика | Когда использовать |
|-----|--------|-------------------|
| `collision` + что угодно (по умолчанию) | **Box** — ограничивающий AABB меша | пол, стены, платформы, прямоугольные блоки |
| `collision_ramp…` | **Convex hull** по вершинам геометрии | пандусы, скаты, наклонные поверхности |
| имя содержит `cylinder` (без учёта регистра) | **Cylinder** (`btCylinderShape`) | колонны, круглые опоры; для `CylinderGeometry` берутся параметры радиуса/высоты |

Примеры имён: `collision_floor`, `collision_wall_north`, `collision_ramp_stairs`, `collision_cylinder_pillar`.

### Рекомендуемый workflow в Blender

1. Смоделируйте **видимый** уровень (graybox, текстуры, свет).
2. Добавьте **отдельные** простые меши под физику:
   - пол — тонкий куб или плоскость с именем `collision_floor`, совпадающий по размеру с видимым полом;
   - стены — боксы `collision_wall_…`;
   - склон — меш с именем `collision_ramp_…`, повторяющий форму пандуса.
3. Коллайдеры можно не текстурировать; при экспорте glTF они всё равно скроются, если имя начинается с `collision`.
4. Убедитесь, что коллайдер **пересекается** с тем, где должен стоять игрок: без `collision_*` тела игрок падает сквозь визуальную геометрию.

### Отладка

При включённом `debugPhysics` в игре рисуются зелёные wireframe-объёмы созданных тел — удобно проверить, что пол и стены на месте.

## Лестницы (ladder)

Лестница — это **игровой объём** (AABB меша), а не физическое тело. Игрок цепляется к нему при подходе и нажатии W/S.

### Как пометить лестницу

| Способ | Условие |
|--------|---------|
| Имя меша | начинается с `ladder` (регистр не важен), например `ladder`, `ladder_shaft_01` |
| Custom Property | boolean `ladder` = `true` |

В Blender: добавьте **куб** (или другой меш), растяните его так, чтобы он покрывал всю зону подъёма — от низа до верха лестницы, с небольшим запасом по ширине. Назовите `ladder` или включите свойство `ladder`. Визуальную модель перил/ступеней можно оставить отдельным декоративным объектом; для геймплея важен именно объём с меткой ladder.

Рядом с лестницей обычно нужны **коллайдеры** (`collision_*`) для ступеней/площадок, иначе игрок не сможет встать на них после слезания.

### Управление в игре

- **W** — подъём, **S** — спуск (нужно стоять рядом с объёмом лестницы и двигаться по вертикали).
- **A / D** — сойти в сторону, пока на лестнице.
- **Пробел** — отцепиться (прыжок с лестницы).
- На лестнице гравитация отключается, горизонтальное движение ослаблено; вертикальная скорость задаётся отдельно (~3.2 м/с).

Объём лестницы строится из bounding box меша в мировых координатах после загрузки сцены — масштаб и позиция объекта в Blender должны соответствовать реальному проёму лестницы.

## Точки респауна (кратко)

Меш с Custom Property `respawn` = `true` (checkbox) регистрируется как точка появления игрока. Центр и размер берутся из AABB меша. Подробнее см. [README.md](./README.md).

## Способ 3: Создать карту программно (Node.js)

Используйте библиотеку `three` с `GLTFExporter`:

```bash
npm install three
```

Затем запустите скрипт для генерации карты.

## Текущее состояние

Код загружает GLB из `client/public/models/` (например `map_test1.glb`). После экспорта из Blender:

- добавьте меши `collision_*` под пол и препятствия;
- при необходимости — объёмы `ladder` для подъёма;
- при необходимости — меши с `respawn` для точек спавна.

Поместите GLB в папку моделей и перезагрузите страницу.
